# 06 第一批 AI 小功能

Type: grilling
Status: resolved

## Question

第一批 AI 小功能:用户点名 1~2 个具体功能(原话「后续还需要往上添加其它小功能,会涉及到 skill 的调用」),作为 AI 底座的第一批消费者与验收样例。每个要具体到:输入是什么、调什么 tool/skill、输出在前端哪里呈现。这是 HITL——功能只能由用户说,agent 不得代答。

## Answer

(2026-08-21 会话解决;用户确认「ok」收票。)

### 框定修正(推翻原票面)

**没有「系统级 AI 功能」**:新标签页系统本身零 AI 入口,传统逻辑即可。AI 能力的唯一消费面 = **未来新增的「扩展类型」图标内部**(用户口语「自定义图标」,按领域词汇正名为「扩展类型」,CONTEXT.md 已定义的扩展点)。原票要求的「点名 1~2 个系统功能」不成立——地图 Destination 成分「第一批 AI 小功能清单」相应改写为「AI 图标类型的消费契约」。

### 第一个验收样例:滴答清单图标

接入 [`@suibiji/dida-cli`](https://help.dida365.com/articles/7464976698707017728)(官方定位「可供 AI Agent 调用」)。五个要素:

| 要素 | 定案 |
|---|---|
| 输入 | 图标摘要无输入(拉今日待办);详情容器(Drawer/Modal 实现时定)内一个自然语言输入框 |
| AI 部分 | 一句话(「明天下午3点提醒我交报告」)→ gpt-5-nano agent 解析 title/due/priority → 编排调用 tools |
| tools | `list_projects`、`list_tasks`、`create_task`、`complete_task`(内部走 CLI 还是直连 Open API,留 07) |
| 输出 | 图标摘要 = 今日到期未完成数;详情容器 = 任务列表 + 勾选完成 + 自然语言建任务;验收链:一句话 → 任务出现在滴答 App + 容器刷新 |
| 降级 | 解析失败 → 回澄清问句、不建任务;tool 失败(token 过期/网络)→ 容器错误态、数据不动。**写入型降级 = 「宁可不动、不可错写」**(读侧沿用 ADR-0005「透传原文、永不空白」,方向相反) |

**AI 边界**(框定的镜像):图标内部大部分是传统逻辑——列表展示、勾选完成直接调 tool/接口,不过 agent;AI 只活在自然语言入口那一段。

### 三个小决策

1. **单例**(同更新日志):token 全局一份、绑定一个滴答账号,非单例无意义。
2. **token 位置**:`DIDA_API_TOKEN` 进 `.env`(沿用 `AIHUBMIX_API_KEY` 习惯,线上追加式维护),不做前端配置 UI。
3. **摘要刷新**:打开页面按需拉 + 短 TTL 缓存(天气档先例),不做定时预取。

### 供 07 使用的事实(dida CLI 文档实测)

- 认证:浏览器 OAuth(`dida auth login`,容器内不便)或 **API 口令**(网页版 设置 → 账户与安全 → API 口令 手动创建 token,`dida auth token` 写入)。
- 命令面:`project list` / `task create --title --project` / `task complete` / `task delete`,另有习惯、专注记录、纪念日的基础操作。
- CLI 本质是滴答 Open API 的一层壳 → 接入形态三分叉(spawn CLI 子进程 / 直连 Open API / import 包编程 API)移交 07。

### 词汇注

「滴答清单图标」词条**暂不进 CONTEXT.md**——词汇先于实物会污染现势词汇表;实现落地时随「AI 扩展类型」一族一起进。

### 勘误(2026-08-21 同日,用户挑战「直接调 CLI 即可」后二次定版)

上面「第一个验收样例」的定位**作废**。逐项复核:摘要 / 列表 / 勾选 / 表单建任务**全部零 AI 可实现**;AI 唯一增值 = 自然语言入口的交互形态升级(非能力升级)。用户拍板:

1. **滴答清单图标 = 纯传统扩展类型**:全功能直调滴答 API(复刻天气的后端代理模式),零 AI、零 agent。上表「AI 部分」「tools」两行作废;接入路径(spawn dida CLI vs 直连 Open API)由实现 session 定,倾向直连 API(CLI 是 Open API 的壳,后端直连少一层子进程)。
2. **AI 底座降级为「设计落档 + 最小骨架」**:02 的选型结论保留为纸面架构;MCP client 从「必建」降为「设计预留」;首个 AI 图标立项时再长全。自然语言建任务若将来真想要,即那时的首个 AI 消费者。
3. 仍然有效的部分:单例、`DIDA_API_TOKEN` 走 .env、摘要 = 今日到期未完成数按需拉 + 短 TTL 缓存、详情容器 = 任务列表 + 勾选 + 表单建任务。降级改传统款:取数失败 → 容器错误态。
4. 滴答图标实现排在 Node 迁移之后,作为新后端上第一个新扩展类型;规格以本票为准,无需新票。落地时进 CONTEXT.md 的是普通扩展类型词条(非「AI 扩展类型」)。
