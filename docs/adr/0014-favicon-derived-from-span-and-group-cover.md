# favicon 边长自跨度推导 + 分组封面化

裸 favicon 类型(nav / 分组)的 favicon 边长不再是三档独立像素常量(32/40/48,改造前 Tailwind 的遗留),改为**自相似拼版推导**:`fav = cols×32 + (cols−1)×gridGap`,再乘 iconScale(默认 gap=8 → 32/72/112)。语义:中图标 favicon ≈ 两个小 favicon 紧拼(含一个 gap)、大图标同理,推导在运行时实时读 gap/scale,任何「布局设置」组合下三档推导关系保持。取代 `SIZE_BASE_PX` 常量(其 pad 部分保留为 `WIDGET_PAD_PX`,仅小组件卡内边距沿用,与本次无关)。

动机:常量与画格完全脱钩——默认参数下 medium 画格宽约 250px 而 favicon 仅 40px(1/6),large 画格宽约 379px 而 favicon 仅 48px(1/8),中/大图标在画格里小而空、边缘与相邻小图标参差。推导化后 favicon 边长与占格跨度同源,整排图标的视觉节奏成系统。

高度防护沿用 9020806 / ADR-0013 的既有骨架:`maxHeight: favPx` + `flex-1 min-h-0 aspect-square` 即「min(推导值, 画格剩余高度)」,同档位画格等高 → 收缩天然全体一致(整齐的本质是一致性,而非绝对值)。典型触发:行高偏矮的视口、large 档 iconScale ≳ 1.15。DragOverlay 幽灵脱离画格,固定取推导值。

分组封面化,同 ADR 反转两处前案并留痕:① ADR-0013 明确保留的「分组底板(soft 档、30% 圆角、内压 9 枚迷你图标)」删除;② ADR-0011 的 3×3 迷你预览弃用。收起态改为**首成员 favicon 作封面 + 成员数角标**(角标仅查看态显示,右上让位编辑模式 EditActions;浏览成员走分组弹层,票 08 已承接)。渲染路径与 nav 裸 favicon 完全一致 = 字面视觉一致。弃用预览的硬理由:与 nav 一致的 32px 视觉块内塞 3×3,每子 favicon 仅约 9px、不可辨认,预览在此尺寸下数学不可用。CONTEXT.md「分组」条目的「iOS 文件夹式」表述同步修订为「封面式」。

## 备选方案(已否决)

- **外包矩形重合**(字面的「与小图标边缘严格对齐」:中/大 favicon 外缘 = 所覆盖小图标 favicon 的外缘):medium 需 161px、large 需 290px,而 2 行画格高约 148px、扣名称行后 favicon 可用高度仅约 128px → `aspect-square` 必然压缩、压缩瞬间对齐即破坏,几何上不可行。
- **高度主导推导**(favicon 尺寸取画格高度可用值):medium 与 large 同占 2 行 → 推导出同尺寸,「尺寸=信息密度」的档位区分失效。
- **分组微缩 3×3 预览**(整体缩至 nav 视觉块):每子约 9px 不可辨认(见上)。
