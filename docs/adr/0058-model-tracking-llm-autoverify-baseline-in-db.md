# 模型追踪:LLM 自动核验 + 基线 DB 化,「当天时效」取代人工核验门槛

背景:GPT-6 Astra(2026-09-03 发布)案例复盘——检测链半年零漏检(线索 9-4 00:41 即落库),真断点是「线索 → 人工核验 → 收录」对用户不可见(线索藏在 Modal 折叠列表,图标零提示)且收录依赖「改代码基线 + 构建部署」(本次 2 天)。用户裁决(grill,2026-09-05):新模型必须**当天**出现在模型列表,接受 LLM 自动核验 + 例外触人。

**决策一(推翻 ADR-0025 决策一):档案行入档经 LLM 自动核验,人工降为例外通道。** 轮询产生的待核验线索,当轮走 `callModel` 网关(ADR-0037 闸门自动生效)抓厂家一手信源原文,LLM 判定是否自家新模型并抽取档案草稿;accept 直接入档(`verified='auto'`)+ 当轮产 kind 'updated' 事件(标题带原文——语义保守,`api_available` 等语义化事件仍只出自人工修订,延续「自动不猜语义」);reject(噪音/低置信)线索留表触人(图标徽标 + ntfy 推送);error(LLM 失败)下轮重试。误报防线从「人工门槛」单层换三层:①确定性噪音规则在 def 层硬拦(百炼托管第三方 = 自家前缀白名单外,不进 LLM);②草稿硬校验(枚举合法 + sources 回链必须与核验信源同 host,编造链接进不来);③auto 行前端带「自动核验」标记可发现、每日 VACUUM 备份可回滚,人工修订 = 会话直改表。

**决策二(基线 DB 化):model_archive 即基线唯一真相。** 七个 `*Baseline.ts` 人工核验存量(269 行)+ AA_MODEL_MAP(116 条)2026-09-05 一次性快照为 `modelBaselineSeed.json`(空库首启灌入、存量库回填归属列;此后**不再随演进更新**——它是初始数据不是活配置),代码基线文件删除;启动不再每启 upsert 刷 profile(「代码即配置」退役,人工修订/auto 入库不被部署覆盖)。归属判定(matchEntry/makeIdResolver)每轮从 DB 读行集构建,与代码常量解绑。AA 映射同构 DB 化(model_aa_mapping),同名自动映射(slug 圆点归一与基线行精确相等 + creator 拦跨家,确定性规则非猜测)直接 upsert 补表、当轮带上评测分数——取代 2026-09-01 的「aa: 未映射线索人工补映射」。

**决策三(触达与节奏):双通道通知 + 2h 轮询。** 模型追踪图标标头徽标「N 待核验」(读侧 = 7 天窗内未完结线索,rejected 留表可见、accepted 自然滚出)+ 自托管 ntfy 容器推送(compose 服务,宿主 7801,backend 内网直发不走代理;高熵 topic 即隐私边界,匿名开放自担垃圾风险,升级路径 auth deny-all)。轮询 6h→2h(七家轻量抓取,上游无压力;「当天」的检测延迟上限从 6h 压到 2h)。

**保留不动:** ADR-0025 决策二(档案全局共享、无 user_id)与拒绝项「不开放任意信源配置」(LLM 核验仍只对七家固定信源);月暗文章流无线索、不参与 auto 核验;线索表机制保留(降级为低置信度队列与核验失败重试队列)。

代价与风险:LLM 判定错误面(误报入档带 auto 标记可删、漏报仍走 rejected 触人)——与人工门槛时代的漏检 2 天相比,个人工具取舍接受;种子快照固化后「基线演进史」不再可从代码 diff 考(ADR-0025 时代的行为),修订史即 DB 数据变更,由每日备份承载。

**注记(2026-09-06):决策三的 ntfy 推送通道撤除,触达收敛为图标徽标单通道。** 用户裁决不走手机端订阅——ntfy 的唯一消费形态(手机/Web 订阅 7801)无人使用,通道上线即无消费者,容器与推送代码(notify.ts、compose ntfy 服务、verifyPendingClues 两处调用)整体删除;决策一 reject 触人语义不变(留表 + 徽标)。教训入档:触达通道先有真实消费端再建,「以后会订阅」不是消费端。

**注记(2026-09-10):决策三徽标读侧的时间轴由 last_seen_at 换为 occurred_on,与核验窗同轴(信息智能化票 04,spec 1.1 痛点 1)。** 动因:已完结线索(verify_state 非 NULL)ingest 冻结后 last_seen 停在核验日,旧轴下 7 天内恒占「N 待核验」徽标(生产首发 35 条死线索淹没真增量);换轴后完结/停更线索按事件日期自然滚出,徽标只剩真增量与真待办。教训入档:触达计数的读侧窗口须与其处理队列窗口同轴——冻结行在计数轴上「假新鲜」,而队列早已不再处理它。

**注记(2026-09-10):决策一核验出口由三态完备为四态,error 落表 + insufficient 新态 + reason 落库(信息智能化票 03,spec 1.2/1.4/1.5)。** ①error 从「不写状态只 console.warn」改为落表可观测(核验链断没断库内可查),核验窗含 error 保持下轮重试,徽标不含 error(失败不触人,轮询自愈);②「判别」与「草稿抽取」解耦:LLM 判自家新模型但草稿校验不过(Fable 5.1 误拒的归因形态——信源单薄致规格抽不出,不是判错)不再伪装 reject,新态 `insufficient` 留表触人等人工裁决、不重试(信源 7 天窗内更新概率低,重试 = 每轮烧强模型看同一页,一次定终身);③reject/insufficient/error 附判定理由落 verify_reason 列(误拒可归因是判别问题还是信源问题)。前向兼容:verify_reason 旧代码不读、两新态旧读侧不含,回滚即静默。
