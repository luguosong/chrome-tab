# tile 跨格尺寸:类型声明 size,顺序流不动,AIHOT 3×2 首例

背景:AI 热点单格 tile 块内只有两行(榜首标题 + 源数),榜单的展示价值没出来,用户要求 3×2 大 tile 展示多条热点标题。但 ADR-0016 定死「所有图标一律占 1 格、无尺寸档位」,IconGrid 的行高推导、前后端容量校验、dnd-kit 排序策略全部按等格假设建立。绕不开,必须先建跨格原语。

**决策:图标类型可在注册表声明 `size`(w 列 × h 行,缺省 1×1);渲染层 CSS grid span;位置模型仍是 `(pageId, parentId, sortOrder)` 纯顺序流,一列都不加。**

1. **size 是类型级声明,不是用户档位**:前端 `IconTypeDefinition.size` + 后端 `TYPE_SPANS` 镜像,缺省 1×1。ADR-0016 的「无尺寸档位」精神保留——用户不可调尺寸,类型固定占格;「大图标」是类型的固有形态而非布局设置。
2. **span 只进渲染层**:`grid-column/row: span w/h`,CSS grid flow 自动把后续图标排到跨格块之后。位置无 x/y 坐标、sortOrder 语义不变——这是当初选顺序流模型的根本红利:跨格不触碰拖拽/移动/合并的任何业务代码,只改样式与三处「恒 1 格」假设。
3. **容量口径从「数个数」改「格数和」**:前端 `iconCells/cellsUsed`、后端 `spanOf/cellsOf`,六个校验点同步(POST 新增、move 跨页/移出、dissolve、config blob 全量替换、编辑角标、拖拽预校验)。AIHOT = 6 格,满页语义变为「其余图标最多 75 个」。
4. **网格 8×8 → 9×9(容量 64 → 81)**:为大 tile 腾格;9 列下 3×2 恰占 1/3 宽,比例协调。`gridWidth` 下限 640→768 配套——9 列轨道比 8 列窄 11%,抬下限保「最小画布下 1×1 图标视觉不变」;默认 1024 不动(9 列轨道 ≈106px > 图标标称 84px,宽裕画布本就不钳)。行数 8→9 不加画布高:同样图标数摊 9 列行数反而更少,满页压缩仅在更高的占用率才触发。
5. **AIHOT 大 tile 不复用单格外壳 Tile**:Tile 的 aspect-square + 边长钳制是 1×1 几何,3×2 块自身玻璃材质(glass-soft)+ container-type 字号档照旧、尺寸交给 span 画格撑满。块内形态:标头(名称 + 榜首鲜度)→ 双列滚动榜单(一屏 6 条 = 2列×3行,序号 + 单行截断标题,top-3 序号 accent)。点击派发零新增:条目 `stopPropagation` 外跳事件页,其余区域冒泡到外层 Tag 开详情 Modal(完整榜单,保留)。

**代价与取舍。** 通用原语只有一个消费者(AIHOT)——相比「AIHOT 特判 span」多花的代码是注册表一个可选字段,换来概念干净;下一个跨格类型零成本。dnd-kit `rectSortingStrategy` 仍假设等格:3×2 tile 参与拖拽时碰撞/排序指示可能错位,功能上顺序模型兜底(最坏是动画观感),**不为此换 strategy**——真炸再修。`usedRows = ceil(格数和/列数)` 是**下界**估算(跨格块的 flow 空洞会让真实行数多于估算):行高按更少行分高、图标略偏大,极端满页矮视口下底部可能溢出画布被裁;不模拟 flow(AIHOT 常居页首时空洞极少),溢出可察再升级为逐行模拟。窄屏不特判降档,沿用「几何钳制」哲学(块窄 → cqw 字号同缩 → truncate 保底)。

**已知的双列取舍**:块内 2列×3行而非 3列×2行——3×2 块是横长条,2 列让每条标题宽 ~50%(中文标题可读性),3 列每格窄高、18px 字一行仅容 ~8 字。共识时两可,落码取可读性。
