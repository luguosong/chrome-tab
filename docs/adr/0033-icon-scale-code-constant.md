# 图标缩放撤除用户调节:大小钉死于代码常量

撤销「布局设置·网格」的「图标缩放」滑杆(0.75~2.0、默认 1.5,ADR-0016 引入):调节引发图标展示效果不稳定(用户观察,根因未深查),稳定性优先于灵活性。图标整体大小(favicon 基准、块内边距、小组件字号)改为代码常量 `ICON_SCALE = 1`(`frontend/src/lib/iconLayout.ts` 唯一来源),下游几何/字号公式照旧消费该系数——机制不变,入口撤除;要调整就改这一处常量(用户直接沟通,不走设置)。

**彻底删除而非锁死**:滑杆、`LayoutSettings.iconScale` 字段(shared 类型)、后端读写与范围校验、`layout_settings.icon_scale` 列(SQLite `DROP COLUMN`,`migrate()` 幂等删列首例)全部移除。线上存量值恰为 1(直查 production 库核实),钉死无视觉跳变。旧客户端/旧备份/旧库 ETL 载荷中的 `iconScale` 成为未知字段:读侧 `withDefaults` 丢弃、写侧不再读取、ETL 列清单忽略——**载荷**层面双端静默容忍。**镜像**层面有一道单向门:新后端跑过一次 `migrate()` 后列已删,旧后端镜像(回滚/部分重建偏差)再写该列即 500——部署须前后端同窗重建(既有纪律:改动侧容器须见 Recreated),可逆性让位于彻底删除(同「保留字段锁死」否决口径)。

ADR-0016「iconScale 是图标大小的唯一调节,必须真实生效」至此闭环:几何推导仍真实生效,「用户调节」半句废止(0016 注记已补)。

## 备选方案(已否决)

- **保留字段锁死 1.0(只删滑杆)**:僵尸设置字段与死列;恢复调节走 git 历史即可,不为可逆性留尸(同 ADR-0016 否决「保留字段锁死 small」的口径)。
- **修好调节的不稳定、保留滑杆**:根因未诊断,修复投入与效果无保证;用户实际固定用 1x 一档,调节入口无真实需求。
