# 模型追踪:无人值守数据核验(双段核验 Agent,LangGraph StateGraph)取代人工例外通道

Status: accepted

背景:ADR-0058 把人工降为例外通道,但 rejected/insufficient 仍「留表触人」、insufficient「一次定终身」——日常人工判断并未消除,与「档案持续自动维护、新模型当天可见」的目标冲突。用户裁决(grill 2026-09-13,设计树 43 问全按推荐定案):模型追踪改为完全无人值守,精度序为误报最不可接受 > 漏报 > 延迟,证据不足保持未知或暂缓、永不猜值。本 ADR 记录整套重构裁决。

**决策一(核验协议:双段核验 Agent)**:核验链重建为 LangGraph **TS 低层 StateGraph** 单域图(不引高层 `langchain`/provider adapter/Python 服务;节点复用 LLM Gateway `callModel`,闸门与候选链语义不另起一套)。图 = 「调查 → 复核」两个 LLM 节点:调查节点持**受限只读读取器**(白名单 = 该厂家注册信源 + 档案 + 历史证据,调用次数上限钉常量)多步取证、输出逐字段提案与原文引用;复核节点**零工具**,只看证据与提案。调查 = `coding-glm-5.3`、复核 = `gpt-5.5-free`(互异家族,各一单值键**自锁不降级**;任一不可用或结论分歧即暂缓——同源模型互证不构成独立复核)。核验调用超时放宽 120s(60s 上限是回放 5 条稳定 error 的根因)。出口四类:噪音 / 接纳 / **暂缓**(证据不足或复核分歧,终态——等证据指纹变化自动重开)/ 系统错误(退避重试);信源全败短路 error,不再以占位串进 prompt。最终 SQLite 事务在**图内最终节点**执行(节点重放幂等:WHERE 守卫 + onConflict);调度、取数管道、队列在图外。

**决策二(信源体系)**:每家注册六类一手信源职责(release / catalog / pricing / limits / weights / retirement),LLM 不自由搜索信源;三档刷新节奏——release 2h、catalog + retirement 6h、pricing + limits + weights 24h,档位即各信源的新鲜度预算。字段冲突裁决矩阵**全局单点**(字段 → 有权信源类,如发布日期只认 release、目录在场是 availability 的必要非充分证据、页面消失不构成退役);厂家 def 只登记信源 URL 与 scope 提取(地域/系列归属),不各写裁决。`model_fetch_status` 主键改 (provider, role),六类信源各自标陈旧与恢复。

**决策三(证据与生命周期)**:新**证据表 append-only**——逐字段一行(原文片段、内容指纹、观察时间、裁决模型与时刻、裁决规则版本);字段当前值取该字段最新一行,取代即追加、旧行永不抹除。线索表加 `evidence_fingerprint`:同指纹守终态,指纹变化重置 pending **自动重开**(取代「终态不可覆盖 + 一次定终身」)。269 条存量种子缺证不删除、继续可见;切换后启动补证批次:每日 30 模型,优先级 trainingParams(93.3% 缺)→ 上下文(35.7%)→ pricing(18.6%),约 9–10 天完成,失败退避不阻塞批。

**决策四(调度与 checkpoint)**:2h cron 既驱动轮询也驱动**重扫**——每轮扫运行中/退避中的未终态线程,以相同 `thread_id` 重新 invoke 断点续跑(durable execution 不是 scheduler,重扫是应用责任)。`thread_id` = 线索 + 证据指纹;`SqliteSaver`(sync)checkpoint 仅执行进度,线索账本仍是领域真相;终态线程保留 7 天调试窗后清理,运行中/退避中永不清理。

**决策五(可观测性)**:「数据健康」只读——图标块徽标改「N 源降级」概数(全部健康不显示);Modal 按信源角色展示健康行(六类各自最后成功时间);响应信封加核验链状态(最后成功时间、暂缓堆积数)。「N 待核验」人工待办徽标语义退役。

**决策六(质量门槛与上线)**:回放升级——语料从 DB 快照解耦为可编辑 jsonl(含构造的分歧/冲突场景)、runner 换图编排入口、出口枚举加暂缓/分歧、结果行加段字段;真值**人工终审冻结**在影子期前完成。影子 7 天:新链只读落 jsonl、旧链照常生产,三轴比对(出口对照、新链 accept 提案**全量人工核**、旧 accept 而新暂缓逐条归因)。门槛:误接纳 = 0、真模型漏报不劣于旧链、error 出口占比显著低于 10%——**不达回桌面,不静默调门槛**;达标切换,旧 `verifyClue` 退役不留双链。

**决策七(依赖守门与代码退役)**:LangGraph 仅模型追踪单域接入,pin `@langchain/langgraph 1.4.15` / `core 1.2.11` / `checkpoint-sqlite 1.0.4`;安装后重测 backend 常驻 RSS 与 dist 体积,增量门槛 **~28 MiB**(参照旧仓库实测 import 即 +25–30 MiB),超门槛回桌面重新裁决;本地 `node dist` 验 ESM bundle(动态 require 暗坑)。试点稳定后删除零消费者的自研 `runAgent` 及 `ai/tools`、`ai/mcp` 空壳;译制域不沾 LangGraph。

**显式推翻**:
- ADR-0058 决策一的人工例外通道语义(rejected/insufficient 留表触人、insufficient 不重试一次定终身、四态出口与 7 天核验窗重试语义)→ 本决策一/三。
- ADR-0058 保留项「月暗文章流无线索、不参与 auto 核验」与 OpenAI「无 `Model:` 条目不产线索」豁免 → 本决策二(六类注册表全员纳入)。
- 信息智能化旧 spec(2026-09 过程工件,`.scratch/` 不入库)的「LangGraph 出局、域代码多 callModel 顺序编排」裁决——当时理由为 TS 版 import 即 +25–30 MiB 常驻 RSS 与单进程内存自保哲学;本轮用户裁决翻案(2026-09-13):编排结构价值高于内存代价,内存风险以本决策七的量化守门承接,不再裸奔。
- ADR-0061 决策 2 对 `ai/agent.ts`「保留完整语义」的表述随 `runAgent` 删除 supersede(网关机制本身不动)。

**保留不动**:ADR-0025 决策二(档案全局共享、无 user_id);「不开放任意信源配置」拒绝项(核验 Agent 仍只对七家固定注册信源)。

代价与风险:LangGraph 常驻内存增量(守门 ~28 MiB 内接受,个人单机工具);双段协议每条线索 ≥2 次网关调用,进程级 12s 闸门共享下吞吐减半(2h 窗口量级无压力,回放与补证批次时长翻倍);复核依赖 free 渠道可用性——渠道故障期间全链暂缓堆积,是「暂缓优先于误报」取向的必然成本;补证 9–10 天窗口内误判暴露在每日低剂量批次而非一夜集中。
