# 图标全容器化:块缘 = 格线(iPhone 主屏语言)

所有类型的图标统一 soft 档玻璃块外壳(ADR-0012 材质),块缘铺满画格 = 与网格线严格对齐——对齐由 grid 布局自动保证,零新公式、零 JS 测量。nav 反转 ADR-0013 的裸 favicon 直出(玻璃块回归,favicon 居中块内);分组弃 ADR-0014 的封面化,恢复 ADR-0011 的 iOS 文件夹容器心智,预览改 **3×2 前 6 成员**(块为横条形——画格列宽约 121px > 行高约 70px,3×3 每子仅约 10px 不可辨认,3×2 每子约 20px 是辨认下限)。stock/weather/changelog 零改动(本就是此语言)。

动机是用户对 ADR-0014 落地实测截图的两条反馈:①封面化分组「显示效果像普通 nav 图标」,要的是 iPhone 式容器内缩小图标;②自相似推导(fav = cols×32+(cols−1)×gap,默认 32/72/112)的「对齐」是**数字推导关系**——medium favicon 72px 居中于约 250px 画格,与小 favicon 边缘永不同线。几何根因:iPhone 主屏的整齐 = 一切都是块且块缘合一;我们 favicon 只占画格约 1/4,「favicon 外缘对齐」需 medium 161px / large 290px,远超 2 行画格高度上限(约 128px),正方形 favicon 几何不可达。唯一自洽解是把视觉锚点从 favicon 边缘移到**块边缘**。

faviconPx(ADR-0014)保留,语义微调:推导边长作**块内 favicon 上限**(三档节奏仍来自推导关系;块内可用高不足时由既有 maxHeight + flex 收缩,同档全体一致)。iconScale 语义相应变为:只缩放块内 favicon 与内边距,不改块尺寸(块 = 画格,随布局设置的整体宽度/间距走)。

留痕与教训:这是 ADR-0012 → 0013 → 0014 → 0015 的第二次方向反转,均为视觉决策且无预览确认所致(0013 去底板、0014 封面化都在用户看到实际效果后推翻)。此后视觉类决策应先出对比原型/截图再定案。

## 备选方案(已否决)

- **仅 medium/large 容器化**(保留小图标裸 favicon):大小视觉语言分裂;nav 块若对齐 favicon 外缘(161px)则与铺满画格的股票卡(250px)宽度不一致,引入第三种宽度。
- **favicon 顶格**(不加底板,收到高度上限 ~128px):medium≈large 档位差几乎消失,且距外包矩形仍差几十像素,对齐依然不成立。
- **外包矩形重合 + JS 测量画格行高推导块宽**:引入 ResizeObserver 测量层,复杂度不成比例;块缘铺满画格用 grid 免费获得同一效果。
