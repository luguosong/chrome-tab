# 图标容器分层:小组件卡铺格 + 图标本体块(iPhone 主屏语言)

> **注记(2026-08-20)**:分层语言(小组件卡铺格 / 图标本体块 + 名称外置)不变;文中三档表述(32/72/112、faviconPx 推导、档位 pad)已随 [ADR-0016](0016-icon-single-size-minimal-density.md) 单档化失效,单档 favicon = 32×iconScale,小组件卡一律 1×1。

> **注记(2026-08-23c)**:nav 部分再次反转,回归 [ADR-0013](0013-nav-bare-favicon.md) 的裸 favicon 直出(用户定夺:背景透明,不显示图标背景块)。Tile 架构不变——bare 选项只省略 glass-soft 材质,几何骨架(块边长推导/画格收缩/hover 缩放)与名称行照常;分组玻璃块、小组件玻璃卡、三档材质体系全部不动。至此反复链:0012 → 0013 → 0015 → 0015 注记 2026-08-23c。

容器化分两层(修订:本 ADR 首版把玻璃套在画格层、名称进块,落地后被用户以「nav 图标看着很小」否决,同日修订为下述结构):**小组件类型**(stock/weather/changelog)沿用 soft 玻璃卡铺满画格,卡缘 = 格线对齐(grid 自动保证);**nav 与分组**的玻璃下沉到图标层——squircle 玻璃块(`TileFrame`,圆角 22%)只包图标本体(favicon / 分组预览),名称外置块下方画格上(iOS 主屏层级:块 = 图标本体,文字 = 壁纸层)。块边 = min(faviconPx 推导值 + 2×pad, 画格可用高度),CSS 双上限 + aspect-square 收缩(同档位画格等高,收缩全体一致)。nav 的 pad=0——favicon 撑满块、图形即块(默认参数下三档 32 / 72 / 112px,第三轮用户反馈「图标撑满玻璃套」);分组预览 pad 取小固定值 3px。

分组弃 ADR-0014 封面化,恢复 ADR-0011 的 iOS 文件夹容器心智,预览 **3×2 前 6 成员**(正方形块受画格高所限约 48px,3×3 每子约 10px 不可辨认,3×2 每子约 19px 是辨认下限;块内 pad 用小固定值 3px,iOS 文件夹内边距同样小于 app 图标)。nav 反转 ADR-0013 的裸 favicon 直出(玻璃回归,但层级是图标本体而非画格)。

动机是用户实测截图的三条反馈(两轮):①封面化分组「像普通 nav 图标」,要 iPhone 容器;②自相似推导的「对齐」是数字关系,favicon 外缘永不同线(外包 161px > 高度可用 128px,几何不可达);③画格级容器把名称拉进块内,块成 121×50 横条、favicon 被衬得小。根因收敛:iPhone 主屏的层级是**块 = 图标本体、文字 = 壁纸层**,玻璃该包的是图标不是画格。

faviconPx(ADR-0014)保留原式(fav = cols×32+(cols−1)×gap),favicon 外缘的自相似推导关系在三档间严格成立;块缘 = fav + 2×pad(档位 pad 递增,块缘不构成第二条推导链——视觉锚点是块,块差几个像素不敏感,不为它再拧公式)。iconScale 语义:缩放 favicon 推导基准与 pad,块随之,不改画格。

留痕与教训:ADR-0012 → 0013 → 0014 → 0015 的完整反复链,均为视觉决策且无预览确认所致。此后视觉类决策先出对比原型/截图再定案。

## 备选方案(已否决)

- **画格级容器(本 ADR 首版)**:所有类型玻璃套画格、名称进块——块成横条、favicon 显小,被用户实测否决。
- **仅 medium/large 容器化**(保留小图标裸 favicon):大小视觉语言分裂;nav 块若对齐 favicon 外缘(161px)则与铺满画格的股票卡(250px)宽度不一致,引入第三种宽度。
- **favicon 顶格**(不加底板,收到高度上限 ~128px):medium≈large 档位差几乎消失,且距外包矩形仍差几十像素,对齐依然不成立。
- **外包矩形重合 + JS 测量画格行高推导块宽**:引入 ResizeObserver 测量层,复杂度不成比例。
