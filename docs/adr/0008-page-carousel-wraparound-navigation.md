# 页面环形切换：滚轮/方向键首尾相接,跨页拖拽与多页跳转保持现状

走马灯(Carousel)的 `goTo` 历来用 `Math.max(0, Math.min(count-1, i))` 硬截断,滚到首页/末页再拨滚轮或按方向键时静默无反应。决定把**滚轮 + 左右方向键**这两条"±1"导航改成环形:在首页向上/← 跳到末页,在末页向下/→ 跳到首页。其余导航路径**不变**:PageTabs 点击是绝对下标、从不越界;**跨页拖拽(EdgeDropZone,见 issue 07)保持截断**——拖拽环形会引入"落点越过边缘"的落区复杂度,属另一项 UX,不在本次范围。

环形跳转的动画**不走位置滑动**。从末页到首页的 `scrollLeft` 跨度是 `(count-1) × pageWidth`,沿用现有 `easeOutBack` 位置动画会高速扫过所有中间页、观感错乱。改为**环形时瞬间到位(instant cut)**:`goTo` 判定为"逻辑相邻、物理跨度 > 1 页"(即环形)时跳过 rAF 动画、直接设 `scrollLeft`。判定基于环形条件(下标取模)而非物理距离,以免误伤 PageTabs 的多页跳转——后者保持原滑动,让"跳了多远"可被感知。单页时环形解析回到唯一页、落点即当前位置,不触发 scroll 事件也无状态变化(等同 no-op),行为同今日;仅此种情况隐藏左右箭头(避免死按钮),多页时常驻。左右翻页箭头原本在边界卸载,现改为常驻(在边界处点击即触发环形)。

这是"语义跳跃 vs 连续卷动"的刻意取舍。页面是离散、命名的一等公民(见 CONTEXT.md),环形是"跳一格"而非连续卷动,instant cut 与之相符。被否决的备选——克隆首末页做无缝单步滑动(真正的 infinite-carousel 手感)——在本仓不划算:页面内容动态(图标、拖拽态)、走马灯用 `scroll-snap`、React 重渲染与克隆位重置相互干扰,复杂度与收益不对等。后果:越界方向键/滚轮不再被吞,首尾两端始终可"往回翻";EdgeDropZone 的边界守卫与箭头渲染条件是后续若要把环形扩到拖拽时的改点。
