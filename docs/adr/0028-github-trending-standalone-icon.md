# GitHub 趋势独立图标:HTML 解析抓取 + 默认组合 cron 保热,组合现抓走内存缓存

背景:GitHub Trending 原为「新闻源」之一(仅 repo 名列表,随 ADR-0027 预取落库)。要独立成 3×2 单例图标:块内 Today 趋势榜,详情 Modal 提供口语语言 / 编程语言 / 周期三维筛选。GitHub 无官方 API,trending 页靠 HTML 解析(选择器 2026-08-26 实抓核验);筛选组合(spoken × language × since)是笛卡尔积,不可全预取。

**决策:从新闻源清单剥离;数据走统一后端内存缓存(TTL 1h)——默认组合(今日 + 不限)cron 1h 保热 + 启动预热,其余组合 GET 时现抓;不落库。**

1. **只预取默认组合**:图标卡片是恒定视图(Today 榜),cron 保热一份即开页零等待(对齐 ADR-0027 的「开页零等待」论据);筛选组合是低频探察,现抓 2.4s(ADR-0027 实测同页)可接受。扩大预取(今日 × 每种精选语言)会把抓取量放大 13 倍,换不来的等待收益。
2. **否决组合落库**:为低频探察建组合键 + 条目池表是结构债;内存缓存重启即丢,代价 = 重启后首个非默认组合请求慢一次(默认组合被启动预热吸收)。cron 与 GET 共写同一个 Map,一条缓存路径。
3. **否决前端直连**:无 CORS,同 ADR-0027 理由;后端集中抓取也压住对 GitHub 的请求频率。
4. **失败降级**:TTL 过期现抓失败时回落过期缓存照发(`fetchedAt` 如实陈旧,鲜度位可见),无缓存才 500(前端重试);解析得 0 条视为失败不写缓存(上游改版/风控常见形态,同 news 口径)。
5. **筛选词表精选即白名单**:GitHub 语言全量 300+、口语为几百项 ISO 639 清单,不铺开——精选 13 编程语言 + 10 口语做胶囊,词表同时是后端参数白名单(参数直接进抓取 URL,拒绝任意值)。

**代价与取舍。** 换来零新增表结构、零迁移、一条缓存路径;付出上游改版即坏(HTML 锚点,fixture 测试断路告警)、长尾筛选需求溢出(不在词表的语言/口语无法在本产品筛,直接上 github.com)。旧新闻源的 github 条目池与勾选行在 NewsService 启动时幂等清理。
