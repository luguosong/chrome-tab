# 视频更新走后端持久化 + 定时轮询,弃易失代理

背景:「视频更新」(博主投稿跟踪)需要每博主最近 50 条的历史窗口、跨会话稳定的 24h 新鲜度标记、以及双平台(YouTube/B站)低频取数——B站侧更是必须带登录 Cookie 的长连接型凭据。同仓「AI 热点」先例是易失代理 + 短缓存(请求路径实时拉,不落库),对这三点都无解:代理无历史、缓存会话级即逝、凭据必须进后端。

**决策:博主注册表与视频流持久化落 SQLite(账号级独立表,不塞图标 `data`),后端 1h 定时轮询预取,前端只读库。**

代价与取舍:换得 50 条窗口、24h 红点、凭据隔离与「轮询即天然重试」的自愈降级(连续 24 轮失败标红、不删数据;凭据补齐下轮自愈);付出存储(每博主 ≤50 行快照)、轮询调度器(独立 cron + 单条 promise 尾链,不与更新日志译制通道复用——资源面与节奏不同)、「入库即快照不回删」的语义(上游删片照旧展示,窗口滚动自然淘汰)。
