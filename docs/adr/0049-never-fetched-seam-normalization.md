# 「从未取到」协议归一:200-null 在取数 seam 转 error,消费端二态

背景:「200 + null body = 后端从未成功取到」是后端立法的域三态之一(cachedOrNull 的宁旧勿空/从未成功两臂,ADR-0042;todo 另有「未配置」400 第三态),但这条 wire 知识在前端只活在注释里——`useQuery<T | null>` 的 null 臂是 hook interface 的一部分却不可见,6 个消费点各持 `isError || data === null` 派生 + 一段复述协议的注释(AiHotModal 与 TodoModal 注释几乎逐字相同),漏判 null 臂就把「从未取到」渲染成空态。2026-08-31 架构评审候选 2。

**决策:归一点放前端 wire 客户端 seam(api/client.ts),消费端塌缩为 isPending/isError 二态;严格零行为变化;weather 桶内 null 明确不收。**

1. **`fetchNonNull<T>` + `NeverFetchedError` + `retryUnlessNeverFetched` 单点 api/client.ts**(与 `apiFetch` 同居——协议知识住 wire 客户端,比住 hooks 贴语义):queryFn 一行换调用、泛型去 `| null`;`NeverFetchedError` 是可区分 class(retry 谓词据此分支);命名对偶 backend `common.ts` 的 `cachedOrNull`(OrNull 表形状)。收编面:aihot×3 + todo 共 4 个 queryFn、5 个消费点(AiHotModal×3、TodoModal、TodoIcon)。
2. **retry 谓词而非 `retry: 1`**:throw 会把 query 接进 TanStack 整包 error 语义,`retry: 1` 对 NeverFetchedError 同样生效——每轮 5/10min 轮询双请求 + 默认 1s 退避,失败 UI 迟 1 秒。谓词 `!(err instanceof NeverFetchedError) && count < 1`:该态不重试,网络错保「重试一次」原语义(v5 谓词形式无独立上限,retryer 全凭返回值,`count < 1` 即上限——failureCount 从 0 起,已在 retryer.cjs 核验)。不重试的立论按准确机制记:cachedOrNull **失败不落 TTL 缓存**(catch 直接 `lastGood ?? null`),前端重试是真打上游,但「从未成功」是分钟级持续失败(上游挂/限额),翻盘概率远低于确定的双请求 + 退避成本;自愈交轮询(interval 回调在 error 态无条件续跑,v5.101.4 queryObserver 已核)与手动重试钮。
3. **零行为对账(等价项)+ 两处已知微变记档**:等价——失败 UI 时机(谓词排除 retry,无退避延迟)、每轮轮询请求量(1 次)、自愈链(null-success 轮询 ↔ error 态轮询均续)、同域失败文案(消费点自持,error 不带文案)、todo「未配置」400 分支(`error instanceof ApiError` 与新 class 互斥)、Modal 内容区(failed 时 error pane 替代,不渲染派生数据)。**微变 ①(修正向,宁旧勿空对齐)**:曾有数据后转「从未取到」(如后端重启冷缓存 + 上游仍挂)时,旧代码 null-success 把缓存 data 覆写为 null、块内(TodoIcon/AiHotIcon)清空闪空;新代码 error dispatch 保留旧 data(v5 `case 'error'` 为 `...state` spread,源码注释自陈「flag existing data as invalidated」)——块内沿用最近成功数据,详情 Modal 仍显示失败;从未有过数据时块内照旧空白。**微变 ②(自愈加速器)**:error dispatch 置 `isInvalidated=true`,`isStaleByTime` 恒真——outage 期间 refetchOnWindowFocus 不再受 staleTime 压制(旧 200-null success 会刷新 dataUpdatedAt),每次窗口 focus 真打一次后端(后端失败无负缓存,转发上游;有 FETCH_TIMEOUT 防挂死)。方向与省 retry 相反,但同属失败态重试通道,且后端恢复后 focus 即自愈。TodoIcon 判定塌缩 `data === undefined || data === null` → `!data` 在无旧数据时等价,有旧数据时并入微变 ①。
4. **乐观工厂泛型收窄**(ADR-0044 涟漪):todo 缓存不再落 null,`optimisticCallbacks<TodoBundle | null, …>` 收窄为 `<TodoBundle, …>` + 注释同步;工厂与工厂测试零触碰——通用件的 null 双层判空契约仍被工厂测试背书,写门 `prev != null` 对 undefined 同样成立。
5. **明确不做**:① weather 收编——`Record<string, WeatherBundle | null>` 的桶内 null 是**分桶部分失败**协议(一条响应部分城市成功部分 null,且经 IconDataContext 跨层下发),queryFn 级 throw 会把部分失败升格为整体失败,是行为变更不是归一;若收编是另立候选(桶级取数 helper)。② 后端改 wire 消灭 null——三态是 ADR-0042 立法的域语义(空 ≠ 从未成功),wire 是忠实投影,前端归一是消费端镜像而非协议改造(回空对象会把失败渲染成「今日日报还未出刊」空态)。③ 乐观工厂改造(见 4)。
6. **grep 契约断言**(镜像 ADR-0045/0046 先例):`apiFetch<…| null>` 泛型在 frontend/src 非测试源码仅许 client.ts(fetchNonNull 自身)与 useWeather.ts(桶内 null)——新域以裸 `T|null` 漏网时测试直接红,强制作者在 seam 处自觉选择;行为面(throw/透传/谓词真值表)直测进 client.test。
